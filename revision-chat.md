## Claude responded: Menentukan MVP itu soal fokus ke masalah paling inti yang dialami hampir semua mahasiswa terlepas dari jenjangnya, sebelum menambah kompleksitas.

Menentukan MVP itu soal fokus ke masalah paling inti yang dialami hampir semua mahasiswa terlepas dari jenjangnya, sebelum menambah kompleksitas. Berikut analisis prioritasnya:

### Prinsip Penentuan Prioritas

Fitur MVP idealnya menjawab **masalah paling umum & paling menyakitkan** (pain point) yang dialami mayoritas pengguna, bisa dibangun dengan effort wajar, dan langsung terasa nilainya sejak pemakaian pertama.

### Fitur MVP (Wajib Ada di Versi Awal)

**1\. Template & Outline Builder sesuai Pedoman Kampus**

-   Kenapa prioritas: Ini masalah paling universal — hampir semua mahasiswa struggle dengan format (margin, penomoran, sistematika BAB) di awal
-   MVP scope: Template dasar untuk skripsi/tesis/disertasi + kerangka BAB I-V yang bisa di-custom

**2\. Manajer Sitasi & Daftar Pustaka Otomatis**

-   Kenapa prioritas: Pain point besar, memakan waktu, dan sudah ada standar jelas (APA/MLA/dll) yang gampang diotomasi
-   MVP scope: Input referensi manual/import → generate sitasi dalam teks + daftar pustaka otomatis

**3\. Tracker Progres & Timeline Sederhana**

-   Kenapa prioritas: Masalah manajemen waktu adalah keluhan nomor satu (banyak yang skripsi molor karena tidak terstruktur)
-   MVP scope: Checklist per BAB + persentase progres, tanpa perlu fitur kolaborasi rumit dulu

**4\. AI Writing Assistant Dasar (parafrase & tata bahasa)**

-   Kenapa prioritas: Nilai jual pembeda yang kuat, dan teknologi (LLM) sudah matang untuk ini
-   MVP scope: Cek grammar Bahasa Indonesia ilmiah + saran parafrase, belum perlu fitur analisis kritis mendalam

**5\. Fitur Komentar/Anotasi Draft (kolaborasi dasar dengan pembimbing)**

-   Kenapa prioritas: Bimbingan adalah proses inti — tanpa ini platform hanya jadi "alat nulis solo", bukan alat skripsi yang sebenarnya
-   MVP scope: Pembimbing bisa kasih komentar di draft, versi sederhana dulu (belum perlu video call terintegrasi)

### Fitur yang DITUNDA ke Fase Berikutnya (bukan MVP)

-   Integrasi statistik (SPSS/R) — kompleks, bisa pakai tools eksternal dulu
-   Generator slide presentasi — nice-to-have, bukan kebutuhan inti
-   Forum komunitas — butuh massa pengguna dulu baru bernilai
-   Manajemen publikasi jurnal — spesifik untuk S2/S3, bisa ditambah setelah validasi awal
-   Cek plagiarisme terintegrasi — bisa mahal (API Turnitin), pengguna sering sudah punya akses lewat kampus

### Kenapa Urutan Ini?

Kelima fitur MVP di atas mengikuti **alur kerja alami** mahasiswa: mulai nulis (template) → cari & kutip referensi (sitasi) → pantau progres (tracker) → perbaiki tulisan (AI assistant) → dapat masukan pembimbing (komentar). Ini menciptakan **loop lengkap** dari nol sampai draft siap sidang, tanpa perlu fitur mahal/kompleks di awal.

### User Story & Spesifikasi Teknis: Template & Outline Builder

#### 1\. User Stories

**Sebagai mahasiswa baru memulai skripsi/tesis/disertasi:**

-   Saya ingin memilih jenjang studi dan universitas saya, agar sistem otomatis menampilkan format yang sesuai pedoman kampus
-   Saya ingin mendapat kerangka BAB I-V (atau struktur lain) secara otomatis, agar saya tidak bingung harus mulai dari mana
-   Saya ingin bisa mengedit/menyesuaikan sub-bab sesuai kebutuhan penelitian saya, karena setiap topik punya struktur yang sedikit berbeda
-   Saya ingin melihat contoh/panduan singkat di setiap bagian (misal: "Latar Belakang harus memuat masalah, data pendukung, urgensi"), agar saya tahu apa yang harus ditulis
-   Saya ingin format (margin, font, spasi, penomoran halaman) otomatis sesuai standar, agar saya tidak perlu atur manual di Word

**Sebagai dosen pembimbing:**

-   Saya ingin bisa melihat progres pengisian outline mahasiswa saya, agar saya tahu sejauh mana perkembangannya sebelum sesi bimbingan

#### 2\. Alur Pengguna (User Flow)

```
1. Onboarding → pilih jenjang (S1/S2/S3) + pilih universitas (atau "generik" jika belum ada)
2. Sistem tampilkan pilihan jenis penelitian (kuantitatif/kualitatif/campuran/studi kasus, dll)
3. Sistem generate outline otomatis sesuai kombinasi jenjang + jenis penelitian
4. User bisa: 
   a. Pakai outline default
   b. Tambah/hapus/ubah urutan sub-bab
   c. Lihat panduan singkat per bagian (tooltip/expandable)
5. User mulai menulis langsung di masing-masing bagian outline
6. Dokumen otomatis mengikuti format kampus (margin, font, heading style)
7. User bisa export ke .docx / PDF kapan saja
```

#### 3\. Struktur Data (Contoh Skema Sederhana)

```
Template
├── id
├── nama_universitas (nullable, "generik" jika umum)
├── jenjang (S1 / S2 / S3)
├── jenis_penelitian (kuantitatif / kualitatif / campuran / studi kasus)
├── format_dokumen
│   ├── margin (top, bottom, left, right)
│   ├── font_family
│   ├── font_size
│   ├── spasi
│   └── penomoran_halaman
└── outline_default (list of Bab)
      └── Bab
          ├── judul_bab
          ├── urutan
          ├── panduan_singkat (teks bantuan)
          └── sub_bab (list, recursive structure)

UserDocument
├── id
├── user_id
├── template_id (referensi ke Template)
├── outline_custom (hasil modifikasi user dari outline_default)
├── konten (isi tulisan per bagian)
├── created_at / updated_at
```

#### 4\. Fitur Teknis Utama

| Fitur | Deskripsi |
| --- | --- |
| **Template selector** | Dropdown/search universitas → jika belum ada di database, fallback ke template generik nasional (mengikuti pedoman umum Kemendikbud/format APA) |
| **Dynamic outline generator** | Kombinasi jenjang + jenis penelitian → generate struktur BAB berbeda (misal: kualitatif tidak selalu pakai hipotesis) |
| **Drag-and-drop editor** | User bisa reorder/tambah/hapus sub-bab tanpa merusak struktur format |
| **Contextual guidance** | Tooltip/expandable box di tiap bagian berisi panduan singkat + contoh kalimat pembuka |
| **Auto-formatting engine** | Style otomatis (heading 1/2/3, margin, font) di-lock sesuai template, user tidak perlu atur manual |
| **Export engine** | Generate .docx dengan format yang sudah sesuai (bisa pakai library seperti python-docx atau docx.js di backend) |

#### 5\. Skenario Edge Case yang Perlu Dipikirkan

-   **Universitas belum terdaftar di sistem** → sediakan opsi "request template baru" atau pakai template generik + custom manual
-   **Perubahan pedoman kampus di tengah jalan** → perlu versioning template (template v1, v2) agar mahasiswa yang sudah mulai tidak terganggu
-   **Struktur non-standar** (misal: skripsi berbasis karya/tugas akhir desain, bukan riset biasa) → sediakan opsi "outline kosong" untuk fleksibilitas penuh

-   % pengguna yang menyelesaikan outline penuh (semua BAB terisi minimal judul + sub-bab)
-   Waktu rata-rata dari onboarding sampai outline pertama selesai
-   % pengguna yang export dokumen (menandakan mereka benar-benar pakai untuk menulis, bukan cuma coba-coba)

## Claude responded: User Story & Spesifikasi Teknis: Manajer Sitasi & Daftar Pustaka Otomatis

### User Story & Spesifikasi Teknis: Manajer Sitasi & Daftar Pustaka Otomatis

#### 1\. User Stories

**Sebagai mahasiswa yang sedang menulis:**

-   Saya ingin menambahkan referensi (jurnal, buku, website) dengan mudah, agar saya tidak perlu mengetik ulang detail bibliografi secara manual
-   Saya ingin mengimpor referensi dari file (misal: hasil export Mendeley/Zotero, atau file BibTeX) agar tidak perlu input satu-satu jika sudah punya koleksi
-   Saya ingin mencari & menambah referensi langsung dari database jurnal (Google Scholar, Sinta, DOAJ) tanpa keluar dari platform
-   Saya ingin menyisipkan sitasi dalam teks (in-text citation) hanya dengan mengetik nama penulis/judul, lalu sistem otomatis format sesuai gaya yang saya pilih (APA/MLA/Chicago/Vancouver)
-   Saya ingin daftar pustaka di akhir dokumen ter-generate otomatis dan terurut sesuai standar, berdasarkan referensi yang sudah saya sitasi
-   Saya ingin bisa ganti gaya sitasi (misal dari APA ke Vancouver) dan semua sitasi + daftar pustaka otomatis berubah format, tanpa perlu edit manual satu-satu
-   Saya ingin diberi peringatan jika ada sitasi dalam teks yang referensinya tidak ada di daftar pustaka (atau sebaliknya), agar tidak ada kesalahan saat sidang

#### 2\. Alur Pengguna (User Flow)

```
1. User klik "Tambah Referensi" di dalam editor dokumen
2. Pilih metode input:
   a. Cari otomatis (search by judul/DOI/penulis → tarik data dari database eksternal)
   b. Input manual (isi field: penulis, tahun, judul, penerbit, dll)
   c. Import file (.bib, .ris, atau export dari Mendeley/Zotero)
3. Referensi tersimpan di "Reference Library" milik user (terpisah dari dokumen, bisa dipakai lintas dokumen)
4. Saat menulis, user ketik "@" atau klik ikon sitasi → muncul daftar referensi → pilih → sistem otomatis sisipkan sitasi dalam teks sesuai gaya yang dipilih
5. Daftar pustaka di akhir dokumen ter-update otomatis setiap ada sitasi baru
6. User bisa ganti gaya sitasi kapan saja dari dropdown pengaturan → seluruh dokumen re-format otomatis
7. Sebelum export, sistem jalankan "consistency check" → tampilkan warning jika ada mismatch
```

#### 3\. Struktur Data (Contoh Skema Sederhana)

```
Reference (milik user, reusable lintas dokumen)
├── id
├── user_id
├── tipe (jurnal / buku / prosiding / website / skripsi-tesis / lainnya)
├── penulis (list, mendukung multi-penulis)
├── tahun
├── judul
├── sumber (nama jurnal/penerbit/situs)
├── volume / issue / halaman (nullable, tergantung tipe)
├── doi / url (nullable)
```
